# 第二阶段：库存与出入库页面路径

依据已确认的十天执行计划第 2 阶段，以及用户允许移除原始家庭收纳界面的新要求。

## 本阶段交付

- 四个主入口：工作台、库存、分析、我的。
- 库存搜索与全部 / 低库存 / 临期 / 缺货筛选；分类与库位筛选。
- 商品详情、批次收起 / 展开、批次信息、入库 / 出库 / 移库页面入口。
- 收货和出库入口：拍照、语音、手动、待确认。
- 可编辑的本次会话草稿；核对标记、编辑、删除和数量提示。
- 移除旧首页、旧分类、旧库房、家庭物品编辑、用完 / 评价以及旧底栏的路由注册。

## UI 字段约定

| 对象 | 字段 |
| --- | --- |
| 商品 | 名称、分类、基础单位、安全库存；汇总数量由批次计算 |
| 批次 | 批次编号、数量、可选效期、库位、人工优先出库标记 |
| 入库草稿 | 商品名称、正整数数量、单位、批次编号、可选效期、库位、可选供应商、可选非负单件进价 |
| 出库草稿 | 已有商品、可用批次、正整数数量、原因（补到货架 / 报损 / 其他）、去向 |
| 通用草稿 | 来源（手动 / 拍照 / 语音）、照片 URI、可编辑转写文本、核对状态 |

这些是 UI 字段约定，下一阶段再冻结 Room 的主键、外键、事务和迁移结构。

## 状态与边界

- 正式入口没有运行时样例库存，不从旧 Item 表冒充仓储商品。
- Debug APK 的“界面预览”启动独立 Activity，使用标明的示例库存；不向 Room 写数据。Release 不包含此 Activity。
- 会话草稿使用 ViewModel 内存状态，旋转与页面返回时可继续核对；进程结束后不保证保留。
- 正式确认入库 / 出库按钮保持禁用，库存记账尚未接入。
- 同一批次的全部出库草稿共同参与可用量校验；报损原因明确保留。
- 过期和零库存批次不可出库；可用量排除过期批次。过期批次仍可查看，排在临期之前。
- 临期窗口暂为 7 天；其后按人工优先出库、正常排序，同状态按效期排序。
- 没有效期的批次在同状态中排在最后；效期允许为空，不推断日期。
- 当前不支持过期品入库；已过期的填写日期会提示核对。
- 相机照片只作为核对依据，返回统一字段表单。语音服务和商品识别尚未接入。
- 销售区仅作为去向记录；没有售卖区库存和真实消费者销量。
- 旧界面退出导航，旧数据表、相机、录音、通知和备份能力继续保留供后续迁移与复用。
